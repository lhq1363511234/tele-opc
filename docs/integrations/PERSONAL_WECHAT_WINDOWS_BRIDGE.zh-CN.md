# Windows 个人微信桥接客户端

## 架构

```text
Windows 微信桌面端
→ TeleOpc.WechatBridge
→ WechatDriver（统一消息驱动）
   ├─ 已初始化的本地读取器（若可用）
   └─ 微信 4.1 兼容驱动（本地截图 + Windows OCR）
→ POST /api/bridge/v1/messages
→ A- 人格、记忆与业务上下文生成回复
→ bridge_outbox
→ Windows 客户端领取待发消息
→ 发送前重新识别聊天标题并校验联系人
→ ACK sent / failed
```

飞书作为状态与人工控制面，不通过鼠标操作飞书桌面窗口传输数据。客户端界面不要求用户选择 OCR、数据库或 UIA 等技术实现；由 `WechatDriver` 自动选择当前可用能力。

## 微信 4.1.11 兼容说明

当前微信 `4.1.11.55` 的 `MMUIRenderSubWindowHW` 没有公开联系人、消息和输入框的完整 UI Automation 控件树，因此基于 `pywinauto`/UIA 的第三方驱动不能作为正式消息驱动。

正式客户端使用本地兼容模式：

- 优先观察微信消息通知窗口；
- 以低频会话列表变化检测兜底；
- 仅发生变化时执行 Windows 本地 OCR，避免持续高 CPU；
- 截图只在本机临时处理，不上传；
- 发送前再次识别聊天标题，无法确认联系人时阻止发送；
- 微信完全收进托盘、主渲染窗口不可用时进入等待，不把它报告成服务器故障；重新打开一次微信主界面后自动恢复。

## 客户端调节项

- 自动回复 / 观察模式；
- 暂停与恢复；
- 是否处理群聊（默认关闭）；
- 轮询间隔；
- 服务器地址与设备令牌；
- 微信诊断导出；
- 托盘后台运行。

旧版数据库密钥提取不再作为主界面操作入口，也不影响兼容驱动工作。

## 安全与可靠性

- 自动回复默认关闭，完成真实联系人端到端验收前不得自动开启；
- 群聊默认关闭；
- 设备令牌只在创建时返回，服务器仅保存 SHA-256 哈希；
- 入站使用 `device + messageId` 幂等；
- 回复队列使用 PostgreSQL `FOR UPDATE SKIP LOCKED` 和 60 秒租约；
- 客户端发送后必须 ACK，失败会保留错误；
- 外部聊天内容作为不可信数据，不允许直接调用高风险工具；
- 设备配置文件生成在发布包中，不提交 Git；
- UIA、OCR 或身份校验失败时均采用“阻止发送”，不采用猜测发送。

## 首次验收

1. 保持 Windows 微信已登录，并打开一次微信主界面；
2. 启动客户端，确认状态为“微信 4.1 兼容模式”；
3. 保持“自动回复”和“处理群聊”关闭；
4. 等待任意真实联系人发送一条新消息；
5. 确认服务器收到正确的联系人名称和正文，且没有自动发出任何回复；
6. 再单独执行一条指定联系人的受控发送测试，确认标题身份校验和 ACK；
7. 只有收、发两条链路均通过后，才考虑开启普通联系人自动回复。
